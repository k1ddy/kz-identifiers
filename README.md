# kz-identifiers

Валидация, разбор и генерация казахстанских идентификаторов. Без зависимостей,
только стандартная библиотека Python (≥3.9).

**Validation, parsing and generation of Kazakhstan identifiers.** Zero dependencies.

## Модули

| Модуль | Что | Алгоритм |
|---|---|---|
| `iin` | ИИН (12 цифр) | контрольный разряд ДВУ РК, разбор даты/века/пола, генерация |
| `bin` | БИН (12 цифр) | 5 фасетов (дата, тип, подразделение, серия, контроль) |
| `iban` | IBAN Казахстана | `KZ2!n3!n13!c`, 20 символов, MOD-97-10 (ISO 7064) |
| `cards` | банковские карты | 16 цифр, Луна (ISO/IEC 7812) |
| `phones` | телефоны | `+7 7xx xxx xx xx` и запись через `8`, нормализация в E.164 |
| `passports` | паспорта РК/РФ | структурная проверка (контрольных разрядов нет) |

## Пример

```python
import random
from kz_identifiers import validate_iin, parse_iin, generate_iin, validate_iban, generate_iban

# ИИН: проверка + разбор
iin = generate_iin(rng=random.Random(1), birth_date=__import__("datetime").date(1990, 5, 17))
assert validate_iin(iin)
print(parse_iin(iin))          # IinInfo(iin='900517...', valid=True, birth_date=1990-05-17, ...)
assert not validate_iin("123456789012")     # checksum

# IBAN: пример из реестра SWIFT (National Bank of Kazakhstan)
assert validate_iban("KZ86125KZT5004100100")
assert generate_iban("125", "KZT5004100100") == "KZ86125KZT5004100100"

# отрицательные примеры для бенчей ПДн
```

## Частые ошибки (почему детекторы пропускают/ловят лишнее)

1. **KZ IBAN — 20 символов, банк 3 цифры.** Структура по реестру SWIFT/НБ РК —
   `KZ2!n3!n13!c` (напр. `KZ86125KZT5004100100`). Шаблон «буква + 4 буквы + 13 цифр»
   не матчит ни один реальный казахстанский IBAN. Проверяйте MOD-97.
2. **ИИН — ровно 12 цифр с контрольным разрядом.** Десятизначные номера договоров
   и займов ИИН не являются; `is_valid_iin_checksum` не требует валидности даты,
   `validate_iin` дополнительно проверяет дату рождения.
3. **БИН vs ИИН:** в БИН пятый разряд никогда не 0–3 (исключён правилами, чтобы
   БИН не совпадал с ИИН). `validate_bin(strict_facets=True)` это учитывает.
4. **Телефоны:** `8 7xx…` и `+7 7xx…` — один и тот же номер; нормализуйте перед
   сравнением.

## Источники спецификаций

- ИИН, БИН — Правила формирования идентификационного номера / бизнес-идентификационного
  номера, постановление Правительства РК от 01.09.2023 (ред. 18.10.2017 № 649),
  [adilet.zan.kz V2300032918](https://adilet.zan.kz/rus/docs/V2300032918).
- IBAN — [SWIFT IBAN Registry](https://www.swift.com/resource/iban-registry-pdf),
  запись KZ (National Bank of the Republic of Kazakhstan).

- [x] Алгоритм контрольного разряда ИИН/БИН сверен с текстом правил на adilet,
      с работающей в проде реализацией проверки ДВУ и с двумя независимыми
      реализациями (gist adilkhash; ZhymabekRoman/kz-iin-validator).
- [x] Внешние векторы: ИИН `061211600012` (README независимой библиотеки);
      реальные БИН `971240001315` (Kaspi), `941240000193` + `250141018288`
      (Казахтелеком + филиал — фасеты декодируются: резидент, головной/филиал);
      IBAN `KZ86125KZT5004100100` (SWIFT IBAN Registry).
- [x] IBAN и Луна сведены с `python-stdnum` (2000 валидных + 300 мутаций).
- [x] «Мёртвый» префикс ИИН (оба цикла дают 10) отвергается всеми реализациями.
- [ ] Структуры паспортов РК (внутренний/загран) — по regex, принятым в продуктивном
      контуре; сверка с adilet/приказом МВД — в выпуске 0.2.
